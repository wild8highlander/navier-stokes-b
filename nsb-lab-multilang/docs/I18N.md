# Internationalisation in NSB Lab

All editions carry runtime-switchable interface languages. This document
lists the key inventory, the switching mechanics per edition, and how to add
a new language.

## 1. Languages per edition

| Edition | Languages | Switch |
|---|---|---|
| Julia | ru, en | menu item 9 · `--lang` · `NSB_LAB_LANG` |
| Python | ru, en | menu item 9 · `--lang` · `NSB_LAB_LANG` |
| C | ru, en | menu item 9 · `--lang` · `NSB_LAB_LANG` |
| C++ | ru, en | menu item 9 · `--lang` · `NSB_LAB_LANG` |
| Rust | ru, en | menu item 9 · `--lang` · `NSB_LAB_LANG` |
| Go | ru, en | menu item 9 · `--lang` · `NSB_LAB_LANG` |

| **Web** | **ru, en, es, de, fr, zh** | header select · auto-detect (`navigator.language`) · `localStorage('nsb_lang')` |

## 3. Mechanics per edition

* **Julia**: `Dict{String,Tuple{String,String}}` of `key => (ru, en)`;
  `L(k)` resolves the current language, `Lf(k, args...)` caches a compiled
  `Printf.Format` per `(lang, key)`.
* **Python**: same shape, dict of tuples; `Lf` is a tiny %-format walker
  (no dependency on the platform's printf dialects).
* **C/C++**: static `struct { key, ru, en }` arrays; `L()` linear-scans
  (≈60 entries — negligible).
* **Rust**: `const I18N: &[I18nPair]`; `L()` linear-scan. Keys are `&'static
  str`, so no allocation happens on the hot path.
* **Go**: slice of structs; PHP: associative array built in `initI18n()`.
* **Web**: a single `I18N` object keyed by language then key;
  `applyLang()` rewrites every element carrying `data-i18n`, the language
  selector persists through `localStorage`, and first visit auto-detects
  `navigator.language` (falling back to English). Canvas captions for the
  two experiment modes are also translated (`cap_viz` / `cap_viz_tg`).

## 4. Adding a language

**CLI editions**: extend the dictionary structure from 2-tuples to
N-tuples (or add a parallel table) and add the language code to the
`--lang` switch. The Julia/Python `Lf` helpers and the C `L()` resolve by
index — one extra `case` each.

**Web app (recommended path)**: add a new top-level key to the `I18N` object
in `webapp/index.html` with the full key set (copy the `en` block as the
template), and add one `<option>` to the `#langSel` selector. Auto-detection
already includes the two-letter code in the `supported` list.

## 5. Translation policy

* Physics units, flow names in flow cards, and numeric formats are
  **language-neutral** (SI units everywhere; decimal point, not comma —
  the CLI accepts a comma on *input* and normalises it).
* Flow cards print their *documented* quantities in English (they are
  quotations from the primary sources: NHC reports, Voyager papers, etc.),
  while everything the lab itself says (cards' labels, verdicts, menus) is
  translated.
* The PDF articles are English-only: the base-14 PDF fonts (Helvetica)
  carry no Cyrillic glyphs, and embedding fonts would break the
  zero-dependency writer. This is stated in each writer's docstring.
* Verdict check keys are never translated *internally* — the `ck_*` keys
  are stable identifiers used by the JSON/CSV exports and CI; only the
  rendered text is localised via the dictionary.
